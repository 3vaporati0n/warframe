# Warframe Mod 伤害计算器设计规格

日期：2026-08-10  
状态：已完成交互式设计确认，等待规格审阅

## 1. 产品目标

构建一个可公开访问的 Warframe 全栈配装与伤害计算网站。玩家能够像游戏军械库一样，将横版 Mod 卡拖入武器槽位，设置 Mod 等级、槽位极性、战甲增伤技能、武器赋能和目标敌人，并查看军械库数值、目标实伤、DPS、乘区范围和计算引擎实际执行的公式。

准确性是产品边界。正式结果只包含已经从 Warframe Wiki 公式、结构化数据和游戏内测试共同验证的机制。未验证机制不会被估算或静默忽略，相关配装必须显示为不完整结果。

## 2. 首版范围

### 2.1 支持范围

- 主武器与近战武器。
- 武器的普通和次要攻击模式。
- 八个普通 Mod 槽。
- 主武器特殊功能槽与武器赋能槽。
- 近战架势槽、特殊功能槽与武器赋能槽。
- 武器等级、催化剂、Forma、初始极性和用户修改后的槽位极性。
- Mod 卡等级、逐级效果、逐级容量、兼容性、冲突组和槽位顺序。
- 战甲增伤技能、技能强度、触发状态和适用范围。
- 武器赋能等级、触发层数、持续状态和适用范围。
- 敌人等级、生命、护盾、护甲、阵营、身体部位、护甲削减和已有异常状态。
- 军械库面板、平均单次伤害、爆发 DPS、持续 DPS、目标实伤和预计击杀时间。
- 可执行公式、乘区成员、变量来源、Wiki 来源、数据版本与验证状态。
- 用户登录、云端保存、配装历史版本、公开页面、复制配装和分享链接。

### 2.2 不在首版范围

- 副武器、Archwing、同伴武器和载具武器。
- 对玩家完整近战按键连段和实际命中节奏的实时模拟。
- 随机战斗 Monte Carlo 模拟；首版使用确定性的数学期望。
- 点赞、评论、排行榜和社区推荐算法。
- 精确复刻游戏卡框动画与所有视觉特效。横版卡片结构进入首版，卡面资源映射必须正确；未验证图片使用中性占位图，不能显示错误的 Mod 图片。

## 3. 用户体验

### 3.1 主计算器

主界面采用已确认的“游戏感 + 计算器”布局：

- 顶部选择武器、攻击模式和目标。
- 主区域使用 4×2 槽位网格。
- 每个槽位显示横版 Mod 卡。
- 卡片显示图片、名称、等级、效果、适用类别、稀有度、极性和当前容量。
- 下方 Mod 库支持名称、效果、极性、稀有度和兼容性筛选。
- 右侧结果区提供“军械库”“目标实伤”“计算公式”三个视图。
- 拖动已安装卡片会改变槽位顺序；元素组合按照槽位顺序实时更新。

### 3.2 Mod 卡交互

- 玩家将 Mod 从卡库拖入合法槽位。
- 选中卡片后通过等级控件设置当前 Rank。
- 等级变化会同步更新卡面效果、原始容量和极性折算容量。
- 点击槽位极性进入 Forma 编辑；系统显示修改前后容量与 Forma 数量。
- 不兼容或冲突 Mod 不允许放入，并显示明确原因。
- 容量不足允许暂时预览，但配装标记为非法，不能发布为正式配装。

### 3.3 技能和赋能

战甲增益输入流程：

`选择战甲 → 选择增伤技能 → 设置技能强度 → 设置触发状态`

武器赋能输入流程：

`选择赋能 → 设置等级 → 设置触发层数 → 设置持续状态`

每个技能和赋能必须显示所属计算阶段与乘区，不能将所有增伤统一相加。

### 3.4 保存与分享

- 未登录用户可以完整使用计算器，并通过编码 URL 临时分享当前配置。
- 首版账号使用邮箱 Magic Link 登录，不保存用户密码。
- 登录用户可以保存配装、创建历史版本、设置公开状态和获得短分享链接。
- 访客无需登录即可查看公开配装，并可复制成自己的草稿。
- 每个保存版本固定引用一个游戏数据快照和一个公式规则版本。

## 4. 系统架构

技术架构采用 Next.js、TypeScript 和 PostgreSQL，部署为公开全栈网站。

### 4.1 模块边界

1. **Web UI**
   - 武器和目标选择、拖拽槽位、卡片等级、技能与赋能输入、结果展示。
   - 在浏览器内运行计算引擎，实现即时反馈。

2. **Calculation Core**
   - 独立 TypeScript 包，不依赖 React、数据库或 HTTP。
   - 输入标准化配装和数据快照，输出结构化计算步骤、公式 ID 和结果。
   - 浏览器和服务器使用相同包与相同规则版本。

3. **Application API**
   - 登录、保存、版本管理、公开分享、复制配装和数据版本查询。
   - 保存前在服务器重新执行 Calculation Core，拒绝被篡改的客户端结果。

4. **PostgreSQL**
   - 保存用户、配装、配装版本、数据快照、公式规则、验证用例和发布记录。

5. **Data Pipeline**
   - 获取 Public Export、Warframe Wiki 结构化模块和公式页面。
   - 标准化字段、转换公式、应用有来源的人工修正、执行验证并发布不可变快照。

6. **Admin Validation Surface**
   - 查看数据差异、缺少公式的对象、回归失败和待验证规则。
   - 只有所有强制检查通过后才能发布新快照。

### 4.2 数据流

`选择武器 → 加载已发布快照 → 编辑配装 → 浏览器即时计算 → 登录保存 → 服务器重复计算 → 写入配装版本 → 生成公开链接`

## 5. 数据模型

### 5.1 核心实体

- `GameDataSnapshot`：游戏版本、来源时间、Wiki 修订、校验状态和发布状态。
- `Weapon`：类别、攻击模式、基础属性、槽位、初始极性和特殊规则引用。
- `AttackMode`：伤害分布、暴击、触发、射速、弹匣、装填、蓄力、衰减和强制触发。
- `Mod`：内部 ID、名称、图片、类型、兼容性、冲突组、稀有度、极性和 Wiki 链接。
- `ModRankValue`：每个等级的效果值与原始容量，禁止只保存最大等级值。
- `EffectRule`：效果的计算阶段、乘区、叠加方式、适用范围、条件、层数和公式引用。
- `WarframeAbility`：技能强度缩放、适用武器、触发条件、效果规则和来源。
- `Arcane`：等级、层数、触发、持续时间、效果规则和来源。
- `Enemy`：等级缩放、生命、护盾、护甲、阵营、部位和特殊减伤规则。
- `FormulaRule`：结构化表达式、输入变量、作用范围、Wiki 章节、修订版本和验证状态。
- `VerificationCase`：输入、预期值、实测来源、允许取整差异和通过状态。
- `Build`：用户拥有的配装入口、标题、可见性和当前版本。
- `BuildVersion`：不可变配置、数据快照 ID、公式版本、服务器计算结果和创建时间。

### 5.2 逐卡公式模型

每张 Mod 是独立规则实体：

```ts
interface ModCardRule {
  modId: string;
  rankValues: readonly RankValue[];
  effects: readonly EffectRule[];
  conditions: readonly ConditionRule[];
  compatibility: CompatibilityRule;
  wikiSource: WikiRevisionRef;
  verificationCases: readonly VerificationCaseRef[];
}
```

逐级数值直接来自 Wiki 表格或已验证的结构化来源，不假设所有卡片线性增长。例如包含小数取整的等级表必须逐级保存。

膛线 R8 的验证示例：

```text
效果：+135% 基础伤害
原始容量：BaseDrain 4 + Rank 8 = 12
匹配 Madurai 极性：ceil(12 / 2) = 6
```

该示例用于防止把 R8 效果与满级容量混用。

## 6. Wiki 公式注册表

Wiki 中的公式按子系统分布。系统将每条已验证公式转换成可执行表达式树。表达式树同时驱动真实计算、公式展示和自动测试，避免计算逻辑与说明文字分叉。

每个 `FormulaRule` 至少包含：

- 唯一公式 ID。
- 适用武器、攻击模式、伤害类型和目标类型。
- 结构化表达式 AST。
- 输入变量及其单位。
- 所属计算阶段与乘区。
- 同区叠加、跨区相乘、上限、替换和重复应用规则。
- 直接命中、异常种子、异常每跳和特殊减伤的作用范围。
- Wiki 页面、章节和修订标识。
- 游戏验证用例与通过状态。

### 6.1 乘区展示

- 基础伤害组：显示成员和 `1 + Σ加成`。
- 物理与元素组：显示槽位顺序、组合过程和每种伤害权重。
- 暴击组：显示暴击率、层级、倍率和平均期望。
- 多重射击组：显示独立伤害实例与小数弹丸概率。
- 技能组：根据具体技能规则进入基础伤害、元素加成或独立倍率。
- 阵营组：目标相关总伤害倍率，并显式标记异常伤害重复应用。
- 目标防御组：针对每种伤害分别应用护盾、生命、护甲、部位和特殊减伤。
- 异常伤害组：不同异常使用独立公式，禁止复用普通命中流水线。

右侧公式视图必须显示每个变量来自哪张 Mod、哪个等级、哪个技能、哪项赋能或哪个目标条件。

## 7. 计算流水线

1. 校验 Mod 兼容性、重复限制、冲突组和容量。
2. 按槽位顺序构建物理与元素伤害分布。
3. 应用逐卡基础属性规则。
4. 计算暴击、多重射击、射速、弹匣、装填和攻击模式属性。
5. 应用技能、赋能和条件效果。
6. 生成军械库面板结果。
7. 针对每种伤害应用目标生命、护盾、护甲、阵营、身体部位和异常状态。
8. 单独计算异常状态种子和每跳伤害。
9. 计算平均单次伤害、爆发 DPS、持续 DPS 和预计击杀时间。
10. 输出计算步骤、乘区、公式 ID、来源和验证状态。

### 7.1 主武器

首版包括步枪、霰弹枪、弓、狙击枪和光束武器，覆盖普通/次要攻击、多重射击、弹匣、装填、蓄力、伤害衰减、暴击层级、状态概率和持续伤害期望。

### 7.2 近战

首版包括普通攻击、重击、滑行和震地攻击。连击倍率由玩家设置。架势和强制触发只在获得可执行 Wiki 公式与验证数据时参与计算。缺少可靠时序数据的完整按键连段不计入 DPS，并明确显示原因。

### 7.3 随机机制

首版使用数学期望。例如 1.9 多重射击按平均 1.9 个独立伤害实例计算。界面必须标明期望值，不将其描述为每次必定发生的结果。

## 8. 正确性边界

一个效果只有同时满足以下条件，才能进入正式结果：

1. 结构化数据能够确定基础数值、逐级值和兼容范围。
2. Wiki 卡片或机制页面明确说明计算方式、阶段和乘区。
3. 至少一个军械库或游戏伤害测试与公式匹配。
4. 自动回归测试覆盖该规则，差异只允许已记录的游戏显示取整或量化。

不满足门槛时：

- 规则状态为 `unsupported` 或 `unverified`。
- 该效果不进入最终计算。
- 配装结果标记为不完整。
- 界面列出缺少的公式或测试。
- 禁止使用推测值、静默近似或默认零值掩盖失败。

## 9. 错误处理

- 不兼容或冲突 Mod：拒绝放入并显示原因。
- 容量不足：允许临时预览，禁止作为合法配装发布。
- 数据版本过期：保留旧快照结果并提供升级差异。
- 新数据同步失败：继续使用上一个已发布快照。
- 公式执行失败：停止相关结果并显示失败阶段和公式 ID。
- 图片加载失败：显示完整文字信息和中性占位图，不影响计算。
- 客户端与服务器结果不一致：拒绝保存并记录差异。

## 10. 测试策略

### 10.1 逐卡测试

覆盖每张受支持 Mod 的所有等级、效果、容量、极性、兼容性、冲突组和乘区位置。

### 10.2 乘区组合测试

覆盖同区相加、跨区相乘、元素顺序、超过 100% 暴击、多重射击小数、技能强度、赋能层数、阵营重复生效、异常伤害、护甲与近战连击。

### 10.3 军械库 Golden Tests

使用固定武器和配装保存游戏内军械库预期值。结果必须匹配，允许差异仅限测试用例中显式记录的显示取整规则。

### 10.4 实战伤害测试

按照 Wiki Research 方法，优先使用单一伤害类型武器和固定目标验证护盾、护甲、部位、异常与特殊减伤。

### 10.5 客户端/服务器一致性

同一输入必须生成相同公式步骤、公式 ID、验证状态和最终结果。

### 10.6 数据发布门槛

```text
Schema 校验
→ 逐卡等级测试
→ 公式和乘区测试
→ 军械库回归测试
→ 客户端/服务器一致性测试
→ 数据差异报告
→ 发布不可变快照
```

任何一步失败都阻止新快照发布。

## 11. 首版验收标准

- 主武器和近战能够选择正确攻击模式。
- 槽位、架势、特殊功能、赋能、容量和极性规则正确。
- 所有标记为受支持的 Mod 逐级值与 Wiki 一致。
- 每项效果显示乘区、执行公式、来源与验证状态。
- 战甲增伤技能和赋能支持强度、等级、层数与触发状态。
- 军械库和目标实伤分开显示。
- 未验证或非法配置不会输出“完整准确”的 DPS。
- 登录用户能够保存、复制、公开和分享不可变配装版本。
- 旧配装固定引用旧数据快照，并可以预览升级差异。
- 浏览器与服务器计算结果一致。
- 拖动或调整卡片后，结果在正常桌面设备上即时更新。
